Security & data

Business records deserve clear access boundaries.

Business Management System combines account access, role-based workflows, company-separated data and local functionality with cloud synchronization. This page describes those concepts at a high level, without publishing internal security configuration.

Account authentication

Users sign in to access the application. Keep sign-in credentials private and use the account's available security and recovery features.

Role-based access

Admin and Secretary are different roles. Administrative access is not implied for a Secretary account; permissions govern access to business functions.

Company-separated data

The product supports multiple businesses, with business data separated by company. This is a high-level description, not a publication of database policies or internal implementation details.

Cloud synchronization

Cloud synchronization uses an internet connection. Admin and Secretary devices can be in different locations and do not need the same Wi-Fi network.

Local application data

The application also uses local storage and SQLite for local functionality. Local availability does not mean a device has synchronized; check its synchronization status.

Database access controls

Database access controls are part of the application architecture. Detailed keys, policies, credentials and private records are not published on this marketing website.

Business records

Access to business information is controlled through the application and roles. Protect devices and account credentials used to access your business.

Backups

Backup options are available in company settings. Ask for a demonstration of the current backup and restore workflow when reviewing your operational requirements.

Security claims: No system can be described as completely secure. No external security certification or audit is claimed on this site. Contact MI TECH with questions about current product practices.
